# AutoDub 前后端接口合同草案 v0.1

日期：2026-10-08  
状态：PROPOSED。独立于Gradio组件自动API；供前端mock与后端实现对齐，尚未实际服务化。

## 1. 基本约定

- 前缀 /api/v1。JSON UTF-8；时间为ISO8601含时区；片段start/end为秒，end>start。
- job_id、segment_id、operation_id、artifact_id均字符串；序号sequence为递增整数。
- segment_id稳定，不是当前表格行号。说话人拆分产生新ID时提供 parent_segment_id/lineage映射。
- revision 是任务的业务版本。文字/设置变化递增；事件序号、进度更新不递增revision。
- 后端是状态唯一写入方。媒体返回任务内artifact ID及可访问URL，浏览器不用Linux绝对路径。
- 每个任务最多一个运行操作。操作异步返回202；GET查询快照与事件，刷新不停止worker。
- mutation使用 request_id 做幂等键（同键同请求复用结果，同键不同请求409）；expected_revision检查并发编辑。
- 所有接口限本次授权任务。正文文案/日志/文件名按数据处理，不作系统命令或HTML执行。
- 原始日志裁剪/脱敏；API key、环境secret不进入事件/前端。
- 第一版暂停/修改以阶段边界为准。轮询期间不得覆盖正在输入的未保存文本。

## 2. HTTP接口

| 方法与路径 | 用途 | 成功 |
|---|---|---|
| POST /jobs | multipart上传video、target_language、mode=review/auto、request_id；创建隔离任务，不自动执行 | 201 Job |
| GET /jobs/{job_id} | 当前revision、任务/阶段状态、能力、active_operation、成品 | 200 Job |
| GET /jobs/{job_id}/segments?offset=0&limit=50 | 句子分页；返回revision；按start、segment_id排序 | 200 SegmentPage |
| GET /jobs/{job_id}/events?after_sequence=0&limit=200 | 有序增量事件，支持刷新与重连；无事件返回空数组 | 200 EventPage |
| GET /jobs/{job_id}/artifacts/{artifact_id} | 视频/音频/JSON下载或播放；Range支持由服务处理 | 200/206 媒体 |
| PATCH /jobs/{job_id}/segments/{segment_id} | 保存有效source_text或translation_text或candidate_id；不自动重跑 | 200 EditResult |
| POST /jobs/{job_id}/actions | run/resume/pause_after_stage/rework；带from_stage、scope等 | 202 Operation |
| GET /jobs/{job_id}/operations/{operation_id} | 操作状态、当前阶段、failure与结果revision | 200 Operation |

POST /jobs本身是元数据/上传，可以由BackendClient接收Gradio临时文件后发给服务。后端复制到任务独立目录，不能继续依赖Gradio临时路径存活。

EventPage必须包含next_sequence与has_more。历史过期时返回410及snapshot_required=true；客户端先刷新Job/Segment快照，再从snapshot_sequence继续。第一版小任务可完整保留事件。

## 3. Job示例

```json
{
  "job_id": "job_demo_001",
  "revision": 4,
  "snapshot_sequence": 105,
  "mode": "review",
  "status": "waiting_review",
  "current_stage": "tts",
  "source_language": "en",
  "target_language": "zh",
  "active_operation": null,
  "stages": [
    {
      "id": "tts",
      "status": "waiting_review",
      "attempt": 1,
      "progress": {"completed": 8, "total": 8, "ratio": 1.0},
      "review_required": true,
      "model": "scheme3",
      "artifact_ids": []
    }
  ],
  "capabilities": {
    "edit_source_text": true,
    "edit_translation_text": true,
    "rerun_tts_segments": true,
    "rerun_asr_segments": false,
    "edit_timing": false,
    "freeform_instruction": false
  },
  "artifacts": [
    {"artifact_id": "dialogue_full", "kind": "dialogue_audio",
     "url": "/api/v1/jobs/job_demo_001/artifacts/dialogue_full",
     "revision": 1, "stale": false}
  ]
}
```

Job.status枚举：created / queued / running / pause_requested / waiting_review / paused / completed / partial_failed / failed / cancelled。  
Stage.status枚举：pending / queued / running / succeeded / failed / waiting_review / stale / cancelled / skipped。

current_stage是活动/当前等待确认阶段。用户仅查看旧阶段时前端记录selected_stage，不能改变current_stage。tts由多个模型分组执行，逐句actual_engine用于精确显示。

stage ID：separation / asr / ocr / diarization / emotion / translation / light_tts / routing / tts / mixing。前端可把translation/light_tts/routing折叠为“翻译与路由”。

## 5. 事件与增量日志

```json
{
  "sequence": 106,
  "timestamp": "2026-10-08T20:35:00+08:00",
  "job_id": "job_demo_001",
  "operation_id": "op_003",
  "revision": 4,
  "stage": "tts",
  "segment_id": "seg_0007",
  "type": "routing.decided",
  "level": "info",
  "message": "第7句：中文、非长句、angry，计划使用IndexTTS2",
  "data": {
    "planned_engine": "indextts2",
    "rule_code": "zh_en_strong_emotion",
    "rule_version": "scheme3_snapshot_20261008",
    "inputs": {"target_language": "zh", "emotion": "angry",
               "is_long_or_complex": false}
  }
}
```

事件type：
- job.created / operation.started / operation.finished / operation.failed。
- stage.started / stage.progress / stage.completed / stage.failed / stage.review_required。
- segment.updated / artifact.created / log.output。
- routing.decided / tts.fallback / cache.hit。
- edit.applied / results.invalidated / rework.requested。
- job.pause_requested / job.paused / job.completed / job.partial_failed / job.failed。

message可读，data结构化。routing初始计算发生在Step3，事件stage=routing；示例若在TTS重新核对则stage=tts。初始计划和实际fallback分别发事件。

事件按sequence去重。有高sequence但旧revision的worker回报不能覆盖当前revision；取消/过期操作的事件仅作为历史。事件发生时间与seq由服务写入，不从模型文本猜测。

原CLI可临时捕获stdout作log.output；阶段、修改、路由等业务事件由后端明确上报。原Step1关键词匹配不可作为正式阶段状态依据。

## 6. 直接修改

请求：
```json
{
  "request_id": "req_edit_001",
  "expected_revision": 4,
  "field": "translation_text",
  "value": "这是我们最后的机会。",
  "reason": "人工确认译文"
}
```

field允许source_text/translation_text/candidate_id；一次改一个字段。source_text保持时间/说话人和raw ASR，写覆盖层。translation_text及candidate_id锁定人工选择，不允许selector或时长重试静默改文案。candidate_id必须属于当前revision/当前segment有效候选。

响应：
```json
{
  "job_id": "job_demo_001",
  "revision": 5,
  "edited_segment_ids": ["seg_0007"],
  "invalidated": [
    {"stage": "light_tts", "segment_ids": ["seg_0007"]},
    {"stage": "routing", "segment_ids": ["seg_0007"]},
    {"stage": "tts", "segment_ids": ["seg_0007"]},
    {"stage": "mixing", "scope": "job"}
  ],
  "resume_from": "light_tts",
  "requires_review": true
}
```

响应由后端算实际依赖并返回；邻句上下文、同说话人参考文字变化可扩大影响范围。前端不能自己猜需要重跑的IDs。

人工单一译文校验不能强迫生成3个候选，后端要新增human_override分支。若失败422返回原因，不保存为有效译文。

## 7. 运行、继续、暂停、返工

```json
{
  "request_id": "req_rework_001",
  "expected_revision": 5,
  "action": "rework",
  "from_stage": "translation",
  "scope": "segments",
  "segment_ids": ["seg_0007"],
  "force": true,
  "instruction": null
}
```

- run：初次从任务起点执行，review模式自动在约定检查点停下。
- resume：从后端提供的resume_from恢复，含确认上次waiting_review；拒绝缺少必需上游的继续。
- pause_after_stage：只登记暂停请求，worker运行至实际可用阶段边界再停；接口返回实际pause_boundary。
- rework：重新计算指定阶段，旧结果立即标记stale，保持历史可比较。
- from_stage必须属于当前capabilities允许的阶段。现阶段不支持逐句分离/ASR/OCR/说话人重算时返回422 UNSUPPORTED_SCOPE；不假装局部执行。
- instruction第一版必须null；第二版启用翻译instruction后纳入prompt与fingerprint。默认保留manual override；清除人工锁定另需明确参数，不以force隐式清除。
- 重做TTS的force只针对指定ID；不能把整段CLI --force-tts直接当逐句重做。
- 编辑→resume和rework不同：前者使用已保存文案，后者请求模型生成。不能对刚锁定的译文调用retranslate让LLM覆盖。
- 修改后轻量TTS/路由为组合执行；第一版翻译后的人工检查点位于整个Step3结束。
- TTS回到翻译只影响需要更新的依赖；mixed成品始终整体重新生成。

响应示例：
```json
{
  "operation_id": "op_004",
  "job_id": "job_demo_001",
  "revision": 5,
  "status": "queued",
  "from_stage": "translation",
  "affected_segment_ids": ["seg_0007"],
  "pause_boundary": null
}
```

Operation.status：queued/running/succeeded/partial_failed/failed/cancelled。rework输入未修改也要产生新的执行版本/attempt，Job revision增加时回传最新值。

## 8. 错误约定

```json
{
  "error": {
    "code": "REVISION_CONFLICT",
    "message": "任务已更新，请刷新后保存。",
    "current_revision": 6,
    "retryable": false,
    "details": {}
  }
}
```

- 400：请求结构/参数错误；404：job/segment/artifact不存在。
- 409：REVISION_CONFLICT/JOB_BUSY/IDEMPOTENCY_CONFLICT/STALE_CANDIDATE。
- 422：EMPTY_TEXT/TARGET_LANGUAGE_INVALID/UNSUPPORTED_SCOPE/MISSING_PREREQUISITE。
- 413：文件超限；415：文件类型不支持。
- GPU繁忙、模型缺失、API失败等异步运行错误记录Operation.failed或partial_failed及事件，给可操作说明。
- API应提供有限的公开错误；服务器完整traceback留任务日志。

## 9. 后端适配重点

1. 每任务独立temp/output和持久化目录，不能共用final_video.mp4或仅视频stem。
2. 统一稳定ID并保存原ASR到说话人拆分后子句的lineage。
3. 自动检查阶段产物、句子成功数与Step5 gate，不能只看CLI退出0。
4. 运行串行锁/版本一致性，原StateManager写入做原子更新。
5. 翻译/轻量TTS/路由/worker 增加结构化hook，GUI轮询不读取半写JSON。
6. 实现人工文本覆盖与锁定，刷新缓存指纹并保留历史。
7. 受影响句子与TTS参考依赖由后端计算；复用缓存以最新fingerprint为准。
8. 前端通过任务内artifact URL播放，服务提供MIME/Range/版本识别，不能暴露任意文件读取。
9. 按capabilities启用按钮，后端能力未到位时前端禁用并解释，禁止假成功。
