# 逐阶段人工审核补充 v0.3

日期：2026-10-09。用户已授权当前模拟工作台修改；正式后端实现仍待评审。
本补充取代 v0.1/v0.2 中 OCR → Step3 组合审核 → TTS 的检查点安排，原稿作为历史保留。

| current_stage / waiting_review | 当前开放 | 确认后执行 |
|---|---|---|
| ocr | 有效源文、ASR/OCR 依据 | 说话人、情绪 |
| emotion | 情绪识别记录与人工修正 | 翻译、轻量 TTS |
| light_tts | 译文、候选与轻量试听 | 模型路由 |
| routing | 计划模型、命中规则与输入依据 | 正式 TTS |
| tts | 配音试听、重做、试合成、采用和返回上游 | 混音合成 |

- succeeded 仅表示计算完成；waiting_review 表示计算结果待人工确认。不能把模型计算成功宣称为人工已通过。
- 人工模式在上述五处安全暂停；自动模式仍自动执行完毕。前端不得通过仅禁用组件假装 worker 已暂停。
- 过去板块折叠只读，未来板块隐藏；路由时不开放情绪、译文或正式 TTS。运行中已有内容只读，完成态保持全工作台只读。
- 保存保留当前审阅位置，依赖失效与 resume_from 由后端返回；确认才重算。保存单句情绪时，尚未翻译的其他句子不能被局部范围漏掉。
- 译文修改后重新轻量检查，会再次停在 light_tts；确认检查结果后才路由。情绪修改不覆盖原识别或人工锁定译文。
- TTS 返回翻译：局部 rework from_stage=translation，停在 light_tts，之后重新经过 routing / tts。
- 新增明确返回情绪入口：局部 rework from_stage=emotion，停在 emotion，之后依次经过 light_tts / routing / tts。mock 新增 rework_stages emotion；真实后台需声明对应能力。
- 编辑与返工回调须检查最新服务状态、当前检查点和 revision；旧标签页不能跨阶段保存。后台仍应执行服务端权限与并发校验。
- 当前已存在的旧任务从其保留的 current_stage / resume_from 继续，不静默回退已处理阶段；完整新顺序请创建新的 review 模拟任务。

mock 使用现有 stage.review_required / stage.completed / operation.finished 事件，无新增 HTTP 服务或真实媒体。原始 CLI 的拆分、安全暂停、情绪人工覆盖、局部依赖计算需后端适配，不能宣称 ZIP 已原生实现本方案。
