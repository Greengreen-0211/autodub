# Stage 10 前端流程与接口预留核对

日期：2026-10-09。范围：方案 v0.1 的 M1/M2，本机模拟前端。未提供真实 HTTP 服务或执行模型。

## 此次修正

1. 审阅等待没有超时失效。以前 mock 的依赖失效把尚未生成的结果也置为 stale；现未运行步骤保持 pending/灰色，只有已有旧结果显示“待更新”。历史 mock 中 attempt=0 的错误 stale 展示作兼容修正，已有旧产物不会被冒充有效。
2. 保存和继续分开。修改源文后，当前 OCR/其他审阅位置保留，resume_from 表示后续处理起点；仅点“确认并继续”才进入说话人等步骤。文本未变化时不增加 revision、不失效、不重跑。原始 ASR/OCR 保留。
3. TTS 使用和上方相同的 Gradio Soft 控件风格。当前句直接显示轻量/正式状态、计划/实际模型、已保存或实际合成文案、fallback/错误；两个试听播放器和返工按钮直接可见。
4. 阶段块悬停显示详情，移开收起；取消 details/open 的点击固定展开。键盘 focus-visible 可查看同一提示。执行动态记录仍可点开依据，不受此修改影响。

## 接口评审补充（mock 已采用，正式后端待确认）

- 保留 v0.1 的 pending/stale 枚举。pending 是未生成；stale 是已有结果因编辑/返工不再适用，前端显示“待更新”，不是时间过期。
- current_stage 保留当前审阅位置，resume_from 用作后续起点；保存 PATCH 不自动执行。
- EditResult.invalidated 只列实际已有旧结果失效；可选 affected 表达完整后续依赖计划（含尚未生成步骤）。mock 的 pending_edit 是可选展示提示，不替代 resume_from。
- 相同有效源文、相同已锁定译文可返回 unchanged=true，不增加版本、不产生失效记录；仍先执行 expected_revision 检查。
- artifact ID 引用需能在任务 artifact 元数据中找到，提供 stale/mock/kind/URL。当前 mock 的 URL 全为 null。
