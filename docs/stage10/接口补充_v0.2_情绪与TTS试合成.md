# 情绪修正与 TTS 试合成：接口补充 v0.2（待后端评审）

日期：2026-10-09。当前仅 `frontend/` 内 mock 实现；不覆盖原接口 v0.1，不代表服务器已有这些接口。

## 路由理由

后端提供 `routing.reason` 和 `routing.decided.data.reason`，前端直接显示，原规则码、输入、阈值和版本仍保留供展开核查。按冻结 Scheme3 策略选择：非中英 → OmniVoice；中英长句/复杂句 → Confucius4；angry/sad/fearful/disgusted → IndexTTS2；happy/surprised → CosyVoice3；neutral 短句 → F5-TTS。

长句依据实际译文长度/复杂度，不能把原声时长直接当成长句路由阈值。当前 mock 默认汉字 28、英文词 20、分句 3，理由列出实际数量和命中阈值。附图的 RTF 0.52 是方案描述，不是当前任务的测量结果，UI 不填该数。

## 人工修正情绪

沿用 `PATCH /jobs/{job_id}/segments/{segment_id}`，增加字段 `emotion_label`。值限定 neutral/angry/sad/fearful/disgusted/happy/surprised，带 request_id、expected_revision，与文本编辑同样事务/幂等/409 校验。

Emotion 增补：`origin=model|human`、`recognized_label`、`human_pinned`、`status=pending|success`。原 `raw_label/score/reliable/fallback_reason` 保留，不把人工标签写成模型识别或伪造置信度。`label` 是当前有效路由情绪；人工覆盖优先于原识别的低可靠性回退。历史保留修改前情绪与路由。

引导式 UI 在路由审阅检查点开放情绪选择，TTS 阶段只读，需返回翻译后修改。保存不运行，当前检查点保留；本句 routing/tts 和成品需更新，译文、ASR、OCR、轻量候选和其他句配音保留。实际依赖由正式后端确认；mock 从 routing 重新计算。确认校验情绪和译文是否有未保存草稿。

## 模型试合成

Job 增加 capabilities：`edit_emotion`、`trial_tts_models`、`adopt_tts_trial`。缺失能力时 UI 禁用；正式服务应明确返回。

Job.tts_engines 为后端模型能力目录：`[{engine, available, languages, mock}]`。UI 仅列可用且支持目标语言的模型，不凭路由规则假定服务器模型已经安装。mock 中四个专用模型示例支持 zh/en，OmniVoice 示例支持 zh/en/ja；这不替代服务器能力核查。

沿用 POST actions：

```json
{"request_id":"req_trial_1","expected_revision":7,"action":"trial_tts",
 "scope":"segments","segment_ids":["seg_0001"],"engine":"cosyvoice3"}
```

一次一个稳定句子 ID，在 TTS 审阅/完成/部分失败时发起；要求当前译文、路由有效、无 active_operation。返回 kind=tts_trial 的 Operation 和 trial_id，状态 queued/running/succeeded/failed。试合成不覆盖自动路由、不使原正式配音或已有成品失效。期间暂停按钮禁用；当前 mock 试合成自行结束并恢复原检查点。正式服务可另行扩展取消语义。

Segment.tts_trials 存储每次独立结果：trial_id、segment_id、revision、engine、actual_engine、status（queued/running/success/failed）、stale、input_fingerprint、text、emotion、audio_artifact_id、actual_duration、duration_error、duration_quality、inference_seconds、rtf、error、mock、created_at。采用前只用于比较。试合成固定请求模型，不悄悄 fallback；正式服务若允许回退须明确实际模型并由用户确认。

所有测量缺失为 null；mock 没有真实音频，artifact.url=null。真实服务须提供可播放媒体和质量/时长门禁结论，UI 不自动断言哪个声音更好。

## 采用结果

```json
{"request_id":"req_adopt_1","expected_revision":8,"action":"adopt_tts_trial",
 "scope":"segments","segment_ids":["seg_0001"],"trial_id":"trial_abcd"}
```

后端校验归属、成功状态、非 stale、依赖指纹及有效媒体。不同句、失败/未完成、旧文案/情绪/参考依赖或过期媒体均拒绝。正式服务还须按质量门禁决定是否可采用。mock 中 successful 占位仅演示交互，不代表质量达标。

采用才提升任务 revision：保留旧正式 TTS 历史，旧音频失效，本句 `tts` 指向选中试合成音频，记录 `model_origin=human_trial` 与 `selected_trial_id`。自动 routing 计划和依据保留，与实际采用模型分开显示；人工采用后不伪装成路由算法选择。成品标 stale，仍停 TTS 审阅，全部句有效后确认从 mixing 重新合成。若还有失败句，保留 partial_failed 门禁。

上段的旧音频失效针对原正式产物；未改变依赖的试合成录音保持有效，可在多个模型结果之间比较并再次采用先前结果。采用只移动正式引用，不因引用变化把试合成文件作废；编辑依赖才使这些录音 stale。

本次采用是选择当前结果，不永久修改自动路由策略；“仅重做当前句 TTS”仍按当前有效自动路由执行。文本、情绪、参考依赖编辑或返工使关联试合成 stale，不能再采用旧结果。

新增事件：tts.trial_requested / tts.trial_started / tts.trial_completed / tts.trial_adopted；相关 segment.updated/artifact.created 保持增量快照同步。

正式后端待确认：能力目录/目标语约束、情绪覆盖接入方式、真实参考依赖指纹、试合成质量门禁、媒体版本与 Range/鉴权、GPU 串行调度。M3 定向指令、时间/说话人编辑仍禁用。
